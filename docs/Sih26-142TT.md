# SIH26142 — Deep Learning Based Super Resolution Mapping (SRM)

## Space Technology | NTRO | Software

> **Objective:** Convert medium-resolution Sentinel-2 imagery (10 m) into a scientifically validated **<4 m super-resolved product** while preserving spatial structure, spectral consistency, geospatial alignment, and uncertainty information.

---

## 1. Problem

Sentinel-2 provides wide-area coverage and frequent revisits, but its 10 m bands cannot reliably represent fine-scale objects such as:

- small buildings
- narrow roads
- field boundaries
- water edges
- localized disaster damage
- small agricultural structures

A conventional image upscaler can make an image look sharper without recovering scientifically useful information.

This project therefore treats super-resolution as a **remote-sensing reconstruction problem**, not simply an image-enhancement problem.

### Critical scientific constraint

A model cannot recover information that was never observed with certainty. A <4 m output will contain **model-inferred details**.

Therefore, the system must:

1. preserve information present in the original Sentinel-2 image,
2. learn plausible high-frequency spatial structure from high-resolution references,
3. preserve spectral relationships,
4. report reconstruction uncertainty,
5. validate the result against independent high-resolution reference data.

---

We propose a **Physics-Guided Residual Swin Transformer SRM pipeline** with:

- Sentinel-2 preprocessing
- paired low/high-resolution training data
- multi-scale feature extraction

- spectral-consistency constraints
- spatial reconstruction losses
- degradation-aware training
- uncertainty estimation
- geospatially aligned GeoTIFF output

# 3. Why This Approach

## Weak approach we deliberately avoid

Simply applying:

```text
Sentinel-2 → Bicubic → 4× Upscale
```

does not solve the actual problem.

It increases pixel count but does not reconstruct reliable fine-scale information.

## Why not make a diffusion model the primary model?

Diffusion models can produce visually impressive details, but for scientific Earth-observation imagery they introduce an important risk:

> visually plausible details may not correspond to real ground features.

For a competition prototype where **scientific reliability and spectral consistency** matter, a deterministic reconstruction model with explicit physical/spectral constraints is a safer primary architecture.

A diffusion model can later be investigated as an experimental branch.

# 4. Target Architecture

## 4.1 Backbone

### Residual Swin Transformer

The main network uses a Swin-style hierarchical transformer because satellite scenes contain both:

- local structures: edges, roads, roofs, field boundaries
- larger structures: fields, urban blocks, water bodies

Windowed self-attention provides a practical compromise between CNN locality and global/contextual reasoning.

### Architecture

```text
Input Sentinel-2 Tile
        │
        ▼
Shallow Feature Extraction
        │
        ▼
 ┌───────────────────────┐

        │
 ┌───────────────────────┐

        │
 ┌───────────────────────┐

 └───────────────────────┘

        │
        ▼

        │
        ▼

        │
        ▼

```

# 6. High-Resolution Reference Data

The major challenge is obtaining genuinely useful paired training data.

A high-resolution reference dataset should contain imagery with substantially finer spatial resolution than Sentinel-2 and sufficient temporal/geographic compatibility.

Potential reference sources include:

- commercial very-high-resolution satellite imagery where legally available
- public high-resolution Earth-observation datasets
- aerial imagery where licensing permits
- carefully selected benchmark datasets

### Important

Do not claim that Sentinel-2 itself provides ground-truth <4 m imagery.

The reference image must be independently acquired or derived from a justified high-resolution source.

---

# 7. Training Pair Construction

Directly finding perfectly simultaneous Sentinel-2 / <4 m image pairs is difficult.

Therefore the project should support two training modes.

## Mode A — Real paired training

```text
High-resolution image
        │
        ├── spatial registration
        ├── radiometric harmonization
        └── Sentinel-2 alignment
                │
                ▼
       LR ↔ HR training pair
```

This is the preferred validation route.

## Mode B — Degradation-based training

Start with a high-resolution reference image:

```text
HR reference
    │
    ▼
Blur / MTF simulation
    │
    ▼
Downsampling
    │
    ▼
Noise / spectral degradation
    │
    ▼
Synthetic Sentinel-like LR
```

Then train:

```text
Synthetic LR → HR
```

This greatly increases training-pair availability.

However, synthetic pairs must not be presented as equivalent to real satellite observations.

---

# 8. Degradation Model

The degradation operator should approximate the Sentinel-2 imaging process.

A simplified formulation is:

```text
LR = D(B(HR)) + N
```

Where:

- `HR` = high-resolution reference
- `B` = blur / point-spread approximation
- `D` = downsampling
- `N` = sensor/noise component
- `LR` = simulated low-resolution observation

Training should randomize degradation parameters so the model does not learn one artificial degradation pattern.

---

# 9. Loss Function

The model should not optimize only pixel-wise MSE.

Recommended total objective:

```text
L_total =
    λ1 L_char
  + λ2 L_SAM
  + λ3 L_grad
  + λ4 L_perceptual
  + λ5 L_consistency
```

## 9.1 Charbonnier / robust reconstruction loss

Improves stability compared with pure MSE.

```text
L_char = mean(sqrt((SR - HR)^2 + ε^2))
```

## 9.2 Spectral Angle Mapper loss

Preserves spectral direction:

```text
L_SAM =
mean(
    arccos(
      <SR,HR> / (||SR|| ||HR||)
    )
)
```

This is particularly important for multispectral remote sensing.

## 9.3 Gradient loss

Encourages meaningful boundaries and high-frequency structure:

```text
L_grad = ||∇SR - ∇HR||1
```

Useful for:

- roads
- field boundaries
- building edges
- coastlines
- disaster boundaries

## 9.4 Perceptual loss

Used carefully to improve structural similarity.

It should not dominate spectral losses because generic natural-image perceptual networks are not inherently calibrated for multispectral satellite data.

## 9.5 Consistency loss

The generated SR image should remain consistent with the original observation after applying an approximate forward degradation operator:

```text
D(SR) ≈ LR
```

Therefore:

```text
L_consistency = ||D(SR) - LR||1
```

This is one of the key safeguards against arbitrary hallucination.

---

# 10. Spectral Consistency

The model must preserve physically meaningful spectral relationships.

Recommended checks:

### Spectral Angle Mapper

Measures spectral-vector angular difference.

### ERGAS

Measures global relative spectral error.

### Per-band MAE / RMSE

Checks whether individual bands are being distorted.

### NDVI consistency

For vegetation applications:

```text
NDVI = (NIR - Red) / (NIR + Red)
```

Compare:

```text
NDVI(reference)
vs
NDVI(SR)
```

The goal is not merely a visually sharper image.

---

# 11. Uncertainty Estimation

The system should explicitly separate:

### Observed information

Information supported by the Sentinel-2 input.

### Inferred information

Fine-scale structures reconstructed by the neural network.

A practical uncertainty layer can be created using:

- model ensembles
- Monte-Carlo dropout
- test-time augmentation
- disagreement between multiple model predictions

Example:

```text
SR_1
SR_2
SR_3
SR_4
   │
   ▼
Mean prediction
   │
   ▼
Prediction variance
   │
   ▼
Uncertainty map
```

High uncertainty regions should be flagged instead of presented as equally reliable as low-uncertainty regions.

# 13. Evaluation Framework

Evaluation must be more rigorous than visual inspection.

## Image reconstruction metrics

| Metric | Purpose |
|---|---|
| PSNR | pixel-level reconstruction |
| SSIM | structural similarity |
| MS-SSIM | multi-scale structure |
| SAM | spectral consistency |
| ERGAS | multispectral error |
| RMSE | reconstruction error |
| MAE | absolute error |
| LPIPS* | perceptual similarity |

`*` LPIPS should be treated as supplementary rather than the primary scientific metric for multispectral data.

# 17. Data Leakage Prevention

This is critical.

Randomly splitting image patches from the same geographic scene can produce misleadingly high scores.

Instead:

```text
Train → Geographic Region A/B/C
Validation → Region D
Test → Completely unseen Region E
```

Where possible, also separate dates.

The final test set must remain untouched until model selection is finished.

---

- acquisition alignment

A visually sharp image that is spatially shifted is not a valid remote-sensing product.

# 21. Hardware Strategy

Training a transformer-based SR model on full satellite scenes is unnecessary and inefficient.

Use:

```text
Large satellite scene
        ↓
Small geospatial tiles
        ↓
Training patches
        ↓
GPU training
```

Suggested starting configuration:

```text
Patch size:       128 × 128 LR pixels
Scale factor:     2× / 4× experiments
Batch size:       GPU dependent
Mixed precision:  FP16/BF16
Optimizer:        AdamW
Scheduler:        Cosine decay
```

Exact parameters should be selected experimentally rather than hard-coded as "optimal."

# 22. Training Strategy

## Stage 1 — Baseline

Train a simple CNN/EDSR-style baseline.

## Stage 2 — Transformer

Train the Residual Swin SR model.

## Stage 3 — Spectral constraints

Add:

```text
SAM loss
+
per-band reconstruction
```

## Stage 4 — Physics consistency

Add:

```text
D(SR) ≈ LR
```

## Stage 5 — Uncertainty

Train multiple seeds/checkpoints or use an uncertainty method.

## Stage 6 — Downstream evaluation

Test whether the SR product improves practical analysis.

# 29. Risks and Mitigation

| Risk | Mitigation |
|---|---|
| Hallucinated buildings/roads | forward consistency + uncertainty |
| Spectral distortion | SAM + spectral losses |
| Poor real-world generalization | geographic holdout testing |
| Temporal mismatch | strict acquisition-window filtering |
| Cloud contamination | quality masks |
| Misregistration | automated alignment + validation |
| Synthetic-to-real gap | degradation randomization + real-pair validation |
| Transformer overfitting | augmentation + geographic split |
| Large GPU memory use | tiled training + mixed precision |
| Visually good but analytically useless output | downstream-task validation |
